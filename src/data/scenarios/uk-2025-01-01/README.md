# Scenario dataset: uk-2025-01-01

Status: **placeholder**. This directory is the target location for the real,
versioned, date-stamped dataset described in spec §5 ("Data acquisition plan"),
but the real sources are not reachable from this sandboxed environment:

| Source | Result |
| --- | --- |
| ONS Open Geography Portal (`geoportal.statistics.gov.uk`) | blocked (network egress allowlist) |
| mySociety MapIt (`mapit.mysociety.org`) | blocked |
| UK Parliament Members API (`members-api.parliament.uk`) | blocked |
| `opendata.arcgis.com`, `hub.arcgis.com` | blocked |

`raw.githubusercontent.com` and the npm registry *are* reachable, but no
GitHub-hosted mirror of the current (post-2023 boundary review, used at the
July 2024 general election) Commons constituency boundaries was located in
this session — using an older boundary set (e.g. pre-2015 `PCON13CD` codes)
would silently misrepresent seats that changed in the review, so none was
substituted.

## What's here instead

- `boundaries.placeholder.json` — a synthetic 6-region TopoJSON fixture
  (generated by `scripts/data/build-placeholder-boundaries.mjs`), used only to
  exercise the `SvgMapRenderer` pipeline end-to-end (projection fit, path
  drawing, hover/click events) before real geometry is plugged in.
- `composition.placeholder.json` — matching fictional `Region`/`Seat` data in
  the real shape (spec §4.2), so the Pinia store and UI can be built against
  the final data contract now.

## Replacing this with real data

Run `scripts/data/fetch-commons-boundaries.mjs` from an environment with
access to the ONS Open Geography Portal, then re-point
`src/stores/scenario.ts` at the resulting file. The acquisition steps are
unchanged from spec §5.2 (boundaries → composition → party master list →
scenario snapshots → seat-count validation).
