### P4.0 - Visual audit, art direction, and design tokens `DONE`

**Goal.** Establish the premium visual target before changing screens. The output should be a small
design system that gives later tasks concrete colours, type, spacing, elevation, radius, motion, and
asset rules.

**Depends on.** Phase 3 complete. This task must land before any broad reskin.

**Steps:**

1. Capture baseline screenshots of the title, new-game, load-game, game, expanded party panel, map
   hover, hemicycle expanded state, save panel, help/explanation dialog, and result screen at desktop
   and narrow viewports. Record the strongest and weakest visual patterns.
2. Write the Phase 4 art direction in one page: "modern civic command room" as the north star,
   with references for density, map-room atmosphere, documentary credibility, and premium game UI.
   Explicitly reject generic SaaS dashboards, toy-like party colours everywhere, and decorative
   gradients that do not carry information.
3. Define semantic colour tokens in CSS/Tailwind terms: app background, map backdrop, surface,
   raised surface, border, subtle border, text, muted text, disabled text, player focus, opponent,
   contest, success, warning, danger, data neutral, and party-accent bridges. Include contrast
   notes for dark surfaces and party-colour edge cases.
4. Define typography and number rules: base family, heading scale, panel title scale, dense-table
   text, tabular numerals, date formatting, deltas, money, seat counts, and when uppercase labels
   are allowed.
5. Define surface and layout rules: 6-8px panel/card radii, 1px borders, elevation levels, backdrop
   usage, spacing scale, fixed control dimensions, z-index layers, modal/sheet constraints, and
   rules against nested cards inside cards.
6. Define motion tokens: durations, easing curves, enter/exit transforms, hover/press states, map
   snap behaviour, event arrival treatment, and reduced-motion substitutions.
7. Document asset rules: icon library choice, party mark strategy, portrait placeholder style,
   background imagery style, favicon/app icon direction, and asset licensing notes.

**Files:** `src/style.css`, optional Tailwind v4 theme tokens, optional `src/styles/` design-token
files, `docs/phase4/` visual-audit notes or screenshots, and any shared type/constants needed by
later Phase 4 tasks.

**Acceptance:** the repo has named visual tokens and written art-direction rules that later tasks
can follow. Baseline screenshots exist or are explicitly listed in a QA note. The palette is not a
single-hue reskin, every token has a semantic role, and core text/background combinations meet WCAG
AA contrast before implementation work proceeds.
