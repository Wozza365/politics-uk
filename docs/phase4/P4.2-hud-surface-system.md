### P4.2 - HUD surface system and shared interaction primitives `TODO`

**Goal.** Replace the current repeated `rounded-2xl border-zinc bg-zinc` HUD styling with a
consistent premium component language for panels, modals, icon buttons, tabs, segmented controls,
tooltips, and stat tiles.

**Depends on.** P4.0. Can start before P4.1 finishes if token names are stable.

**Steps:**

1. Create shared primitives for the surfaces that recur throughout the game: `HudPanel`,
   `PanelHeader`, `IconButton`, `SegmentedControl`, `Tooltip`, `StatTile`, `ModalSurface`,
   `DrawerPanel`, and `StatusPill` as needed. Keep the API small and aligned with existing Vue
   patterns.
2. Move border, radius, background, blur, shadow, z-index, and header spacing decisions into those
   primitives or shared utility classes. Reduce most tool-surface radii to 6-8px unless P4.0 chose
   a different token for a specific reason.
3. Standardise panel header hierarchy: title, optional subtitle, close/help/action area, and
   predictable keyboard focus order. Dense panels should not use hero-scale text.
4. Convert top-level game HUD areas first: event feed, party panel, clock, journal, by-election
   panel, targeting panel, save panel, help panel, explanation dialog, hemicycle panel, and view
   switcher.
5. Replace text-only utility controls with icon or icon+text controls where the meaning is familiar:
   close, save, load, import, export, rename, delete, help, target, map, chart, settings, pause,
   play, skip, zoom, and reset. Add accessible labels and tooltips for icon-only buttons.
6. Define empty, loading, saving, disabled, selected, pending, success, warning, and destructive
   states for primitives. States must use shape/icon/text changes, not colour alone.
7. Remove redundant nested cards inside dense panels. Where repeated records need cards, keep them
   visually lighter than the parent surface and stable in height.

**Files:** new or existing shared UI components under `src/components/`, `src/style.css`, all HUD
components currently duplicating surface classes, and component/unit tests where behaviour changes.

**Acceptance:** the game screen reads as one designed interface rather than many similar ad hoc
panels. Repeated HUD styling is centralised, icon buttons are named, focus states remain visible,
and the converted panels pass desktop/narrow screenshot checks without text overlap.
