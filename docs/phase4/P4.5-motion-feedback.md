### P4.5 - Motion, transitions, feedback states, and tactile feel `TODO`

**Goal.** Add polished motion and state feedback that makes the game feel responsive and alive
without becoming noisy or inaccessible.

**Depends on.** P4.0 motion tokens and preferably P4.2 primitives.

**Steps:**

1. Implement a shared motion scale: instant/fast control feedback, medium panel transitions, map
   snap transitions, feed item arrival, save/restore feedback, and slower result reveals. Use named
   CSS variables or helpers rather than ad hoc durations.
2. Add route/screen transitions for title -> new/load -> loading/restore -> game -> result. Keep
   focus management and route timing deterministic so tests are not flaky.
3. Add panel enter/exit transitions for save, help, explanation, targeting, by-elections, party
   expanded, hemicycle expanded, tutorial, and confirmation surfaces. Transitions should not move
   text so far that users lose context.
4. Add micro-interactions: button hover/press, segmented-control thumb movement, selected tab
   indicator, icon-button active state, stat delta flash, feed entry arrival, event action resolved,
   objective completed, save complete, and destructive confirmation.
5. Refine map motion: zoom button steps, active-region snap, hover lift, selection pulse, contest
   callout, and reset. Motion must not cause layout shift around HUD panels.
6. Build reduced-motion substitutions: opacity/focus-state changes instead of movement, no repeated
   pulses, no parallax, and no spinner-only loading state.
7. Add tests or QA notes for reduced-motion mode, route changes, focus return after transitions,
   and no stuck paused/open panel states.

**Files:** `src/style.css`, shared transition components or composables, router/screen components,
HUD panels, `MapView.vue`, feed/action components, tests, and Phase 4 QA notes.

**Acceptance:** the app feels more tactile while remaining calm. Reduced-motion mode is respected
globally, transitions do not break keyboard/focus flow, and screenshots or recordings show no text
overlap or layout jumps during common interactions.
