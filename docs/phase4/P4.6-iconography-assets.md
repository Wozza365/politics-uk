### P4.6 - Iconography, party identity, imagery, and app assets `TODO`

**Goal.** Give the game a coherent visual asset language: icons, party marks, portraits/placeholders,
favicon/app icons, and background imagery that support a premium political-sim identity.

**Depends on.** P4.0 asset rules and P4.2 primitives.

**Steps:**

1. Choose and install a single icon library, preferably `lucide-vue-next`, unless the project has a
   strong reason to use a different set. Wrap icons in shared components so sizing, stroke width,
   labels, and tooltip behaviour stay consistent.
2. Replace manual inline SVG controls and text-only utility buttons with library icons where a
   familiar symbol exists: play, pause, skip, save, folder/open, download, upload, settings, help,
   close, chevrons, target, map, chart, list, search/zoom, reset, warning, trash, edit, and info.
3. Define party identity treatments. Use verified party colours, initials/short names, geometric
   marks, or licensed logos where rights are clear. Never rely on official marks or politician
   photography without an asset-rights decision.
4. Create intentional portrait placeholders for leaders/officers: consistent framing, colour
   treatment, initials/name layer, and optional generated silhouette style. Replace bare text boxes
   with this asset system until real licensed portraits are available.
5. Design the app icon/favicon set and any splash/social image assets. The mark should read well at
   16px, 32px, and larger sizes and should not depend on tiny map details.
6. Add background imagery or generated bitmap assets where they genuinely help: title screen,
   loading screen, scenario briefing, result screen, or subtle map-room texture. Keep imagery
   inspectable and relevant; avoid blurred stock-like decoration.
7. Document asset locations, source/licensing status, generation prompts where applicable, and
   replacement procedure for future real assets.

**Files:** `package.json` if an icon dependency is added, shared icon components, existing
components with inline SVG/text controls, `public/favicon.svg`, optional `public/` or `src/assets/`
image/mark folders, party data if marks are referenced, and asset notes under `docs/phase4/`.

**Acceptance:** icons are consistent, accessible, and no longer hand-rolled per component. Party and
leader visuals look intentional even when placeholder-based. App/favicon assets exist, asset rights
are documented, and no UI depends on unlicensed official marks.
