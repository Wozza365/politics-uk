## Balance Indicators

The headless runner reports:

- Resource solvency: min/max cash by party, with invariant failure below the defined floor.
- Action availability: days each player lever is available in the sampled run.
- Polling range: min/max by party, bounded to the scenario's undecided/rounding envelope.
- Contest results: resolved contest count, player gains, and player contest win rate.
- Election outcomes: applied GE count and reconciled Commons seat totals.
- Objective completion: complete, failed/expired, and active objective counts.
- Save/restore continuity: number of restore checks attempted and matched.

These are guardrails, not automatic design tuning. A dominant no-risk strategy or impossible
progress path should be reviewed by a human before changing action costs, polling magnitudes, or
scenario data.

## Performance Budgets

Baseline: production build, Chromium/Edge-class browser, full `uk-2025-01-01` scenario data,
populated feed/history after a 365-day replay.

| Operation | Budget |
| --- | ---: |
| Initial app load to title screen | <= 3.0s |
| New campaign load to playable game screen | <= 2.5s |
| View switch between supported map/stat views | <= 250ms interaction response |
| Map hover/click interaction | <= 100ms response |
| Autosave write after a domain action | <= 500ms p95 |
| Save restore to playable paused campaign | <= 1.5s |
| Heap after 365-day replay and full scenario load | <= 250MB |

Do not add virtualization, dynamic imports, or `MapRenderer` changes unless a measured run exceeds
these budgets. Preserve the current renderer abstraction when optimizing map work.

## Release Checklist

- `npm run build` passes.
- `npm test` passes, including `src/sim/campaignRunner.spec.ts`.
- `npm run validate:data` passes and scenario provenance/source files are present.
- Clean new-game path starts a campaign with seeded polling history and no stale save state.
- Save, autosave, export/import, and restore compatibility smoke tests pass.
- No-save recovery path surfaces load/write errors without crashing or mutating other saves.
- Keyboard smoke: pause/resume, speed control, event choice, target selection, save/load, and menu
  close all work without a pointer.
- P3.8 accessibility matrix in `docs/P3.8-QA.md` has been reviewed for the release build.
- Largest supported scenario can load, save, restore, and switch views within the budgets above.
- Fixture hash changes are explained in the PR/commit notes when gameplay tuning is intentional.
