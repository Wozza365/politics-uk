### P3.2 — Main menu, load/new-game flow, and safe game lifecycle `TODO`

**Goal.** Replace the one-way MVP start screen with an understandable game lifecycle: choose a new
campaign, continue safely, load an intentional checkpoint, or leave an active campaign without
losing it. This is the player-facing half of P3.0/P3.1—not a second persistence system.

**Depends on.** P3.0 and P3.1. P2.10 improves the new-game scenario picker but is not a blocker.

**Steps:**

1. Extend the UI screen model to distinguish a title/main menu, new-game setup, load-game browser,
   loading/restoring, game, result, and confirmation modal. Keep the source of truth in `ui.ts`;
   avoid a collection of component-local booleans that can conflict after a load.
2. Replace `StartScreen.vue` with a title surface that presents:
   - **Continue** only when a compatible autosave exists, with scenario/party/date metadata;
   - **New game**, leading to scenario → party → difficulty setup;
   - **Load game**, opening the manual/autosave browser;
   - **Settings** (P3.8 may expand it) and a clear game version/build label for save support.
3. Keep the present timeline/party-card picker as the new-game flow. Starting a new campaign must
   confirm when an unsaved/active campaign exists, initialise all mutable stores through one
   `startNewGame` orchestration action, then create its first autosave before/at the first playable
   frame.
4. Build a restoring loading state. Read the save, load/validate its scenario, hydrate stores,
   report a recoverable failure with a route back to the load list, then show the game paused with
   a short “Campaign restored” confirmation.
5. Add an in-game menu reachable by keyboard and pointer: resume, save/manage saves, settings,
   return to main menu, and restart. Opening it reuses P2.8’s shared menu-pause gate; returning to
   the title never clears a campaign until the user confirms and pending autosave work is settled.
6. Update `App.vue`, `LoadingScreen.vue`, and integration tests for every legal screen transition,
   including no-save Continue, invalid loaded save, cancel from destructive confirmation, and
   result → continue / result → menu.

**Files:** `src/stores/ui.ts`, `src/App.vue`, `src/screens/StartScreen.vue`, new
`src/screens/{LoadGameScreen,RestoreScreen}.vue`, game menu/confirmation components, and tests.

**Acceptance:** a player opening the app can immediately continue a valid autosave, choose a
different manual save, or begin a new campaign without ambiguous state. Returning to the title
does not lose progress; failed restore explains the problem and leaves other slots usable. All
menus pause the campaign and restore focus predictably on close.
