### P3.4 — Targeted campaigning and opponent strategy `TODO`

**Goal.** Give players a map-shaped strategic layer and make the other parties respond. National
polling should remain important, but campaign resources need places, electoral stakes, and
counterplay—particularly in P2.8 by-elections and approaching scheduled elections.

**Depends on.** P3.3. Uses P2.8 contest data and the existing tier/map/region abstractions.

**Guardrails.** Targeting must use the real region/tier identifiers already present in scenario
data; it must never invent demographic precision the data does not support. A regional effect has
a defined spillover into national polling, rather than secretly moving only a headline number.
Opponent decisions are deterministic and inspectable, not an LLM or hidden random system.

**Steps:**

1. Define target scopes in `src/types/action.ts`: national, nation/region, electoral tier,
   specific seat/ward, and active contest. Add targetability metadata to regions only where the
   necessary identifiers and statistics exist.
2. Build target selection from the existing map focus/drill-down infrastructure. The selection UI
   shows current holder, prior result/majority, projected competitiveness, player commitment,
   relevant local effects, and any existing party commitments. It must be usable without requiring
   precision pointer gestures.
3. Implement pure targeting resolution: convert an action's resource/time commitment into bounded
   local influence, then translate it into contest probability and/or a transparently small
   national/segment impact. Define stacking, competing-party cancellation, expiry, and how a
   scheduled election consumes accumulated local influence.
4. Add an opponent strategy module. On a deterministic cadence, each non-player party ranks its
   available actions/targets using transparent utility rules (defend marginal held seats, pursue
   plausible gains, respond to player focus, preserve scarce resources). Resolve decisions through
   P3.3's action pipeline and record public-facing summaries where the player could plausibly know
   about them.
5. Keep the AI budget-limited and difficulty-tunable. Scenario/difficulty configuration controls
   resource budgets and aggressiveness; it must not receive hidden free polling or unbounded cash.
6. Add map overlays/filters for player commitments, active contests, and notable opponent activity.
   Do not crowd the base map: every overlay has a legend and can be switched off.
7. Test target validation, locality/expiry, competing commitments, opponent determinism, no action
   when resources are insufficient, and a recorded rationale for selected AI moves.

**Files:** `src/types/{action,region}.ts`, new `src/sim/{targeting,opponents}.ts`, relevant
scenario data, game/campaign store, `MapView.vue`, P2.8 contest UI, new overlay components, and
spec files.

**Acceptance:** a player can invest a scarce campaign action in an eligible place, see its scope
and duration, and later see that it influenced the relevant contest/election through documented
rules. Opponents make bounded, reproducible choices using the same resource system; changing the
player's target can provoke a different but explainable response.
