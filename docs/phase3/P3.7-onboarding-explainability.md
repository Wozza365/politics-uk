### P3.7 — Onboarding and simulation explainability `TODO`

**Goal.** Make the political simulation legible without making the player read a manual. A new
player should know what they are trying to achieve, what they can do now, why time is paused, and
why a poll/contest/election changed. An experienced player should be able to dismiss guidance and
inspect the evidence when they choose.

**Depends on.** P2.8, P2.9, P3.3, and P3.5 for full coverage. It can deliver a small first-run
orientation earlier using existing P2 features.

**Steps:**

1. Define a small set of contextual guidance milestones in data/code: campaign start, first
   player lever, first paused action event, first contest, first targeted commitment, first poll
   release, and first election result. Track dismiss/completion state in player preferences or the
   campaign only where it affects that campaign; do not show the same modal on every load.
2. Build a non-blocking guided overlay with one concise task at a time, visible skip/dismiss
   control, keyboard escape, and no dependence on a fixed screen size. It highlights existing UI
   but never prevents the player from accessing save/quit controls.
3. Add a goal/status strip to the HUD: primary objective, days to next relevant election, current
   highest-priority unresolved decision, and the reason the clock is paused. The player can expand
   it into the campaign journal rather than being trapped in a tutorial sequence.
4. Create a “Why did this change?” drill-down from polling releases, contest outcomes, and election
   results. It presents grouped, player-meaningful contributors: event/action effects, policy
   alignment/salience, local commitments, and bounded variance. Reuse provenance/source action IDs
   from P3.3; do not fabricate false numerical precision.
5. Add glossary/help entries for recurring terms: polling vs projection, national vs local impact,
   resource/cooldown, contested election, and scenario assumption. Link contextual terms to these
   entries; keep the full mechanics reference optional.
6. Test milestone eligibility/dismissal, no duplicate tutorial after restore, focus and escape
   behaviour, and explanation records for representative poll/contest/election resolutions.

**Files:** new `src/types/tutorial.ts` and `src/sim/explanations.ts` as needed; a preferences or
UI store; new guide, help, status, and explanation components; `EventFeed.vue`, `PartyPanel.vue`,
P2.8/P3.5 result UIs; tests.

**Acceptance:** a first-time player can start a campaign, take an action, resolve an event, and
understand the next objective without external documentation. After a poll or contest outcome,
the player can inspect an honest, concise explanation of the recorded contributing factors.
Guidance stays dismissed after save/load and never blocks an exit or save action.
