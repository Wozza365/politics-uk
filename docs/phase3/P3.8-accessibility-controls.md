### P3.8 — Player controls, accessibility, and responsive play `TODO`

**Goal.** Make the game comfortable across a full campaign: the player controls time, can operate
every decision without a mouse, understands visual information without colour alone, and can use
the interface on narrower screens. This is core product work, not cosmetic polish.

**Depends on.** It has no hard dependency, but should be implemented alongside P3.1/P3.2 and each
new panel rather than deferred until Phase 3's end.

**Steps:**

1. Replace the fixed 15-seconds-per-day-only behaviour with explicit time controls: pause/resume,
   supported speed choices, and a clearly labelled current state. Speed changes apply only while
   no menu/action/election pause gate is active; the clock composable remains the sole timer owner.
   Persist player-preferred speed, but restore a loaded campaign paused.
2. Consolidate the existing pause causes into a typed pause-reason set/count (pending action,
   open menu, result resolution, player pause, restoring). The UI reports the highest-priority
   human-readable reason and cannot accidentally resume through an unresolved action.
3. Establish accessible dialog/menu primitives: focus trap, initial focus, Escape behaviour,
   focus return, semantic labels, and no pointer-only trigger. Apply them to clock/election,
   party, map detail, saves, confirmations, results, and tutorial surfaces.
4. Audit colour and contrast against the spec's WCAG goal. Provide non-colour party indicators
   (names/patterns/symbols where needed), visible keyboard focus, legible map/hemicycle selected
   states, and text alternatives for charts. Respect `prefers-reduced-motion`; offer an in-game
   reduced-motion preference if transitions remain essential elsewhere.
5. Make the HUD responsive: define small/medium/large layout breakpoints, compact summaries for
   data-dense panels, scroll-safe modal bodies, and an alternate list/table route to map-dependent
   actions. Touch targets must remain usable; pan/zoom cannot be the only way to select a region.
6. Add automated checks where feasible (semantic roles, keyboard flows, reduced-motion classes)
   and a documented manual QA matrix for Chrome/Firefox/Safari/Edge, keyboard-only, narrow
   viewport, zoomed text, screen reader smoke tests, and high-contrast modes.

**Files:** `src/composables/useGameClock.ts`, `src/stores/{game,ui}.ts`, shared UI primitives,
`style.css`, all menu/panel components affected, plus unit/component tests and a QA checklist in
`docs/`.

**Acceptance:** a player can pause, change speed, resume, save, load, choose an event action, and
select a campaign target using keyboard alone. Any automatic pause explains itself. At 320 CSS px
wide and at 200% text zoom, core controls remain reachable without clipped dialogs or colour-only
meaning; reduced-motion users do not receive unnecessary animated transitions.
